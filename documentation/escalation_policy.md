
# IT Helpdesk Escalation Policy

## Purpose

Establish consistent procedures for transferring
technical incidents requiring additional expertise.

## Level 1: First-Line Support

Responsible for:
- Initial incident intake
- Ticket categorization
- Basic troubleshooting
- User communication
- Incident documentation

## Level 2: Advanced IT Support

Responsible for:
- Complex application issues
- Advanced operating system troubleshooting
- Network configuration issues
- Persistent hardware or software problems

## Level 3: Specialized Support

Responsible for:
- Infrastructure incidents
- Server and enterprise application failures
- Suspected security incidents
- Data integrity concerns
- Vendor-level technical support

## Mandatory Escalation Conditions

Escalate immediately when:
- A potential security incident is identified.
- Multiple employees experience a major outage.
- Sensitive business data may be affected.
- The issue requires unauthorized access or privileges.
- The problem exceeds the technician's scope.

## Escalation Documentation

Every escalation must contain:
- Ticket ID
- Reported problem
- Business impact
- Priority
- Investigation performed
- Findings
- Error messages
- Supporting evidence
- Reason for escalation
- Assistance requested

## Closure Requirements

A ticket may only be closed after:
- The issue is resolved or appropriately handed off.
- The resolution is documented.
- Verification is completed when applicable.
